# Incident response

Triage and contain, preserve evidence, rotate affected credentials, assess taxpayer/tenant scope, eradicate, restore from verified sources, notify authorized stakeholders under applicable law, and publish an appropriate post-incident review. Maintain private contacts, severity definitions, decision logs, and practiced runbooks.

Report suspected vulnerabilities privately through GitHub private vulnerability
reporting or the private security contact recorded in the operational contact
system; never open a public issue containing exploit details, credentials, or
taxpayer data. Record reporter contact, discovery time, affected environment,
safe reproduction, suspected data/tenant scope, and immediate containment.

Security owns severity and notification decisions with legal/privacy
stakeholders. Preserve immutable audit, deployment, identity, database, queue,
and secret-access evidence using correlation and trace IDs. Practice account
takeover, cross-tenant exposure, compromised dependency, credential leakage,
document malware, and outbox integrity scenarios at least annually.
